# 433 Gateway WebUI 改造设计（App 风格）

> 日期：2026-08-09
> 状态：已确认
> 技术栈：Tasmota 15.5.0 (ESP32-SOLO1) + Berry（WebUI/业务）+ C 驱动（`xdrv_74_cc1101.ino`）

## 1. 目标与背景

Tasmota 原生 WebUI 的交互与布局偏向**配置逻辑**，不适合日常操控。改造目标：

1. **默认入口**改为 433 Gateway 的 App 风格界面（类似 Apple HomeKit），适配手机为主的使用场景。
2. 与 433 相关的一切功能（遥控、场景、门磁、事件、管理）全部在 App 界面内完成。
3. Tasmota 原生 WebUI 仅通过 App 内"🔐 Tasmota 系统设置"入口访问（admin）。

## 2. 信息架构

**路由**：默认 URL `/` 直接进入 433 Gateway App 首页；原生界面仅由 App 内入口跳转。

**5 个底部 Tab**：

| Tab | 内容 | 性质 |
|-----|------|------|
| 遥控 | 首页仪表盘：门磁状态行 + 遥控 3 列方形按钮 + 虚拟设备开关 | 日常操控 |
| 场景 | 序列动作列表与编辑（发送/延时步骤） | 日常 + 编辑 |
| 门磁 | 门磁状态卡片（开/关 + 最后变更时间） | 日常监控 |
| 事件 | 时间线（遥控/联动/门磁 彩色类型标签） | 日常查看 |
| 管理 | 遥控管理 / 门磁管理 / 联动规则 / 虚拟设备 / 网关设置 / 🔐 Tasmota 系统设置 | 配置 |

## 3. 视觉风格（Apple HomeKit）

- 浅色背景（`#f7f7f9`），方形圆角（squircle）卡片，图标 + 名称。
- 首页遥控按钮：**每行 3 个**，icon 与文字均在按钮内。
- 遥控子界面：标题在卡片外；卡片内方形 **icon-only 按钮**（icon 在按钮内、文字 label 在按钮下方、按钮 UI 之外），**每行最多 4 个**。
- 门磁状态卡片开/关高亮色；事件时间线类型彩色标签。

## 4. 页面设计

### 4.1 遥控 Tab（首页仪表盘）
- 顶栏：标题"433 Gateway" + 右上 ⚙（点击跳转**管理 Tab**，App 内管理）
- 门磁状态行：2 张开/关变色卡片
- 遥控方形按钮 3 列网格（icon + 名称）
- 多按钮遥控（如卷帘门）：点击进入**全屏子界面**，显示该遥控所有按钮

### 4.2 遥控子界面
- 顶部"‹ 遥控"返回
- 标题（遥控名）在卡片外上方
- 卡片内：方形 icon-only 按钮（每行最多 4 个），文字在按钮下方
- "＋ 添加按钮"管理该遥控的子按钮

### 4.3 场景 Tab（序列动作）
- 场景列表（名称 + 步骤摘要）
- 编辑页：步骤序列（`发送遥控` / `延时`），支持排序/删除/添加，▶试运行 / ■停止
- 场景可绑定虚拟设备

### 4.4 门磁 Tab
- 状态卡片：开/关高亮色 + 最后变更时间
- "＋ 添加门磁"

### 4.5 事件 Tab
- 时间线：时间 + 内容 + 类型标签（遥控/联动/门磁）

### 4.6 管理 Tab
- 遥控管理（录制/编辑/删除）
- 门磁管理
- 联动规则
- **虚拟设备**（HA 暴露配置）
- 网关设置（433 频率/参数）
- 🔐 Tasmota 系统设置（**唯一 admin 入口**，跳转 Tasmota 原生 WebUI）

## 5. 序列动作引擎

### 5.1 数据模型
```
序列 sequence = { name, steps[] }
步骤 step = { type: SEND | DELAY, remote/button, delay_ms }
```

### 5.2 执行模型
- 步骤顺序执行：`发送遥控` 或 `延时`。
- **抢占式单实例执行**：同一时刻只执行一个序列；新序列触发时，立即终止当前序列剩余步骤，从新序列第 1 步开始。
- 延时步骤可被中断（周期检查抢占标志）。
- 提供"停止"命令（终止当前序列）。
- 用途示例：卷帘门开启序列 = 停 → 延时2S → 开 → 延时35S → 停（停在合适高度）。

## 6. 虚拟设备与 HA/MQTT 暴露

### 6.1 概念
- **虚拟设备**是本地配置的逻辑设备（如"车库"）：设备名 + ON 动作（绑定本地序列）+ OFF 动作（绑定本地序列）。
- **序列动作是纯本地概念**，不通过 MQTT 传输。

### 6.2 HA 暴露
- 以设备整体暴露为 Home Assistant switch 实体：`homeassistant/switch/{id}/config`
- `command_topic`：接收开关命令（ON/OFF）
- `state_topic`：上报设备状态

### 6.3 控制链路
```
小米语音"打开车库"
  → HA switch 车库=ON
  → MQTT publish cmnd
  → Tasmota 设备订阅收到 车库=ON
  → 本地执行序列（卷帘门-开启序列）
  → 执行完成后状态上报
```

### 6.4 状态语义（瞬时触发型）
- 收到 ON/OFF **不管当前状态都执行**对应序列（不因状态跳过）。
- 状态立即置为目标值（ON/OFF），序列执行完自动回 OFF（表示动作已执行完毕/空闲）。
- 原因：车库/卷帘门是"动作型"设备，不是持续状态设备；任何状态下都要能执行指令。

## 7. 技术实现要点

- **WebUI 层**：Berry 重构 `cc1101_gateway.be`，页面自绘 HomeKit 风格 HTML/CSS/JS；C 驱动保持现有稳定功能。
- **路由**：`/` 显示 App 首页；App 内"Tasmota 系统设置"跳转原生界面（具体路由方案实施时确认，如 `/admin` 重定向或跳转）。
- **序列引擎**：Berry 实现（步骤状态机 + 50ms 定时驱动 + 抢占标志），支持停止。
- **HA 虚拟设备**：Berry 订阅 MQTT `cmnd` 主题 → 触发本地序列；发布 `tele` 状态；发布 HA 自动发现配置。
- **数据存储**：扩展现有 JSON 文件（remotes / sequences / virtual_devices / doors / links / events）。
